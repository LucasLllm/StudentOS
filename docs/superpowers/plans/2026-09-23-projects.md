# Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Projects: folders of chats that share instructions, a Context of vault notes the agent gathers itself, and a rolling project memory, at a fixed and cached token cost.

**Architecture:** A `projects` table groups `agents` rows. Context is `project_sources` rows pointing at notes in either the project's own vault (`<VAULT_ROOT>/<userId>/projects/<projectId>/`, owned) or the student's vault (linked). On a project chat's first turn a pure renderer freezes a project block (instructions, memory, manifest, and full text when Context ≤ 20K tokens) into `agents.projectContext`; it rides tier 2 of the system prompt, and later Context changes ride `<turn_context>`. Three tools (`project_search`, `project_open`, `project_add`) serve large projects and let the agent add context. A creation sweep and a worker memory pass run in the background.

**Tech Stack:** TypeScript, Drizzle/Postgres, Hono, React 19 (no router lib), plain CSS, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-23-projects-design.md`

## Global Constraints

- Inline threshold: Context ≤ **20,000** estimated tokens (chars / 4) is inlined in full.
- Project memory cap: **6,000 characters** (~1.5K tokens).
- `project_open` part size: **16,000 characters** (~4K tokens).
- Creation sweep: 3–5 queries, at most **8** items added, two `effort: 'low'` calls.
- Source summary: one `effort: 'low'` call, `maxOutputTokens: 200`, result ≤ 160 chars; fallback is the first 160 chars of the body.
- The frozen block is never re-rendered for a chat. Nothing that varies per turn may enter `buildSystemPrompt`.
- No labels distinguishing agent-added from student-added sources.
- House style: "why" comments on decisions, matching surrounding files. Inline SVG icons. CSS in `apps/web/src/index.css` with existing variables.
- Every commit passes `pnpm format:check` (the pre-commit hook enforces it); run `pnpm exec prettier --write` on touched files.

export async function summariseSource(

Block format (byte-stable; sources sorted by `name` then `id`):

```
Project: <name>
The student's goal for this project, in their words:
<instructions>            (section omitted when blank)

What earlier chats in this project established:
<memory>                  (omitted when blank)

Project context (<n> items). Everything below belongs to this project:
- [<id8>] <name> (<kind>): <summary>
...
<either>
Full text of each item follows.
### <name>
<body>
<or>
The context is too large to carry whole. Use project_search to find passages and project_open to read an item.
```

`[<id8>]` is the first 8 chars of the source id; `projectDiff` parses those markers out of the block, compares with `current`, and returns `"Added to the project context since this chat started (open with project_open):\n- ...\nRemoved from the project context: a, b"`. Empty project: manifest line "Nothing has been added to the project context yet." Bodies go through `renderNotes`-style defanging of `<`/`>` for non-student sources — reuse by passing already-rendered bodies (the caller renders with `renderNotes`).

### Task 5: API

**Files:**

- Create: `apps/api/src/projects/access.ts` (DbProjectAccess + `addToProject` + `ingestUpload/Text/Drive/Mail` + `loadBlockSources`), `apps/api/src/routes/projects.ts`, `apps/api/src/routes/projects.integration.test.ts`

Key behaviour:

- `addSource(ctx, { userId, projectId, noteName, noteKind, owned, kind, image })`: reads the note, `tokens = estimateTextTokens(body)`, `summary = summariseSource(...)`, insert `onConflictDoNothing`, bump `projects.updatedAt`.
- `ingestUpload` reuses `importUpload(projectVault(...), file, deps)`; kind from `sourceKindFor`.
- Text: writes an entity note `{ name: uploadNoteName(title), source: 'student', description: title, body }`.
- Drive: builds a `ToolContext` with `BetterAuthGoogleTokenProvider`, calls `readDriveFile.execute`, `textFromDriveRead`; writes entity note (source `drive`, externalId fileId, sourceUrl if present), kind `drive`.
- Gmail: `readMail.execute` → entity note (source `gmail`, description subject), kind `email`.
- Linked vault note: find in student's vault among entity, then document, then episode; kind `document` (or `email` when source gmail, `drive` when source drive).
- Sources GET: `preview` = first 400 chars of body, `image` flag → client uses `/api/uploads/:name?projectId=`.
- DELETE source: delete row; owned → `vault.remove(noteKind, name)`.
- DELETE project: delete row (cascade chats and sources), `rm -r` the project vault directory.
- `GET /projects/:id/chats`: agents where projectId, with last assistant-or-user message content (one query with a lateral/subselect, or two queries) → `preview` ≤ 140 chars; newest `updatedAt` first.
- agent-turn: if `agent.projectId`: load project (owned by user), `sources = loadBlockSources(...)`; if `agent.projectContext` null → render and store; `diff = projectDiff(block, sources)`; add project tools to registry; `project.access = new DbProjectAccess(...)`; attachments read from project vault.
